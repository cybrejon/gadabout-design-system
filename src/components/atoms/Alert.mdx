# Alert

An Alert displays an important, high-priority message or feedback in a non-intrusive banner. It provides users with context-sensitive information, such as success feedback, warnings, system updates, or error logs.

Alerts are designed to be part of the page layout, rather than temporary overlays like Toasts.

## Appearances

The Alert component supports three distinct appearances to fit different layout densities and visual weight requirements:

### Soft (Default)

The soft appearance uses a subtle, translucent background tint with a matching left accent border. It provides high scannability without overwhelming the page content.

<Canvas of={AlertStories.InfoSoft} />

### Outline

The outline appearance features a transparent background with a thin border. It is ideal for low-emphasis messages or embedded blocks in cards.

<Canvas of={AlertStories.OutlineAppearance} />

### Solid

The solid appearance uses a fully filled block of color with high contrast text. It is designed to grab maximum user attention, perfect for critical errors or banner updates.

<Canvas of={AlertStories.SolidAppearance} />

## Semantic Variants

Alerts come in five semantic variants that correspond to different emotional states and brand colors:

- **Primary**: Brand-focused announcements and feature callouts.
- **Info**: Neutral updates and informational messages.
- **Success**: Positive confirmations of completed tasks.
- **Warning**: Advisories about potential actions or limits.
- **Error**: Critical notices about failures or data loss.

## Features

### Dismissible

When `dismissible` is set to `true`, a close button is rendered on the right. The component automatically handles fading out and collapsing when closed, and calls the optional `ondismiss` callback.

<Canvas of={AlertStories.Dismissible} />

### Actions

Provide supplementary actions (e.g., links or buttons) inside the alert using the `#snippet actions` block. These are placed cleanly below the alert text.

<Canvas of={AlertStories.WithActions} />

### Custom Icon

You can override the default semantic icons by providing a custom icon using the `#snippet icon` block.

<Canvas of={AlertStories.CustomIcon} />

### Compact Layout

If no `title` is provided, the alert automatically adjusts its padding and alignment to a compact, single-line format.

<Canvas of={AlertStories.NoTitleCompact} />

## Code Examples

### Basic Alert

```html
<script>
	import { Alert } from 'gadabout-design-system';
</script>

<Alert
	variant="info"
	title="System Update"
	description="Scheduled maintenance will occur tonight at 12:00 AM UTC."
/>
```

### Dismissible Success Alert

```html
<script>
	import { Alert } from 'gadabout-design-system';

	function handleClose() {
		console.log('Success alert was dismissed');
	}
</script>

<Alert
	variant="success"
	title="Settings Saved"
	description="Your profile preferences have been successfully updated."
	dismissible="{true}"
	ondismiss="{handleClose}"
/>
```

### Alert with Custom Actions

```html
<script>
	import { Alert, Button } from 'gadabout-design-system';

	function handleRenew() {
		// handle renewal action
	}
</script>

<Alert
	variant="warning"
	title="Plan Expiring Soon"
	description="Your trial period ends in 3 days. Upgrade to continue using premium features."
>
	{#snippet actions()}
	<button size="sm" variant="outline">Learn More</button>
	<button size="sm" variant="normal" onclick="{handleRenew}">Upgrade Now</button>
	{/snippet}
</Alert>
```

### Compact Single-line Alert

```html
<script>
	import { Alert } from 'gadabout-design-system';
</script>

<Alert
	variant="error"
	appearance="outline"
	description="Failed to sync changes with the server. Retrying in 5s..."
/>
```

## Usage Guidelines

### When to use

- Use alerts to notify users of system status changes or immediate feedback on actions they took.
- Use the `soft` appearance for most standard notifications within forms or dashboards.
- Use the `solid` appearance sparingly, reserved for critical failures or global banner announcements.

### When not to use

- Do not use alerts for fleeting notifications that don't require persistent visibility; use [Toast](?path=/docs/component-atoms-feedback-toast--docs) instead.
- Do not overload a single page with multiple alerts, as this creates visual fatigue.
